# DB-000 — Database Standards

Version: 1.0
Status: Approved

## Purpose
Defines database-wide standards inherited by all schema documents.

## Principles
- One owner per business concept.
- One domain per table.
- Immutable entity identity.
- Explicit relationship entities.
- Earned complexity.

## Naming
- Plural snake_case tables.
- <entity>_id primary keys.
- Full-name foreign keys.
- created_at, updated_at required.
- deleted_at optional.
- status enum; no lifecycle booleans.

## Identity
- Identity never changes.
- External identities (auth.users) are referenced, not duplicated.

## Relationship Entities
Use explicit entities when relationships own business meaning, permissions, metadata or lifecycle.

Example:
student_users
Pending → Active → Revoked

Relationship lifecycles are defined by the owning schema while following these standards.

## Lifecycle
Business lifecycle:
Pending → Active → Suspended(optional) → Archived

Deletion is separate from lifecycle.

## Ownership
Every table defines Purpose and Owner Domain.
Cross-domain foreign keys are allowed without transferring ownership.

## Security
Relationship-driven authorization with RLS.

## Events
Past-tense names.
Events are the canonical asynchronous integration mechanism.

## Governance
Changes require ADR or formal DB-000 revision.
