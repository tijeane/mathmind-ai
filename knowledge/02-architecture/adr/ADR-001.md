# Context

MathMind requires a modern, scalable, cloud-native architecture capable of supporting AI-assisted learning, real-time collaboration, secure authentication, and rapid feature development.

The technology stack should:

* maximize developer productivity
* minimize operational complexity
* support server-side rendering and modern React patterns
* integrate cleanly with PostgreSQL
* provide strong TypeScript support
* support deployment on Vercel
* scale from MVP to enterprise usage

---

# Decision

The project will use the following technology stack.

## Frontend

* Next.js (App Router)
* React
* TypeScript
* Tailwind CSS
* shadcn/ui

## Backend

* Next.js Route Handlers
* Server Actions where appropriate

## Database

* PostgreSQL

Hosted by:

* Supabase

## Authentication

* Supabase Auth

Supported providers may include:

* Email/Password
* Magic Link
* OAuth providers (future)

## Storage

* Supabase Storage

## ORM / Database Access

* Supabase JavaScript Client

Raw SQL migrations remain the source of truth.

## Validation

* Zod

## Forms

* React Hook Form

## Styling

* Tailwind CSS

Component library:

* shadcn/ui

Icons:

* Lucide React

## Hosting

* Vercel

## CI/CD

* GitHub
* GitHub Actions
* Vercel Deployments

## Testing

* Unit: Vitest
* Component: React Testing Library
* End-to-End: Playwright

## AI Integration

* OpenAI APIs

AI integrations must remain behind a service abstraction to allow future provider changes.

---

# Alternatives Considered

## React + Express

Rejected due to additional infrastructure complexity and duplicated routing.

## Firebase

Rejected because PostgreSQL provides stronger relational capabilities and aligns with the approved database architecture.

## Prisma

Deferred.

The project will initially use the Supabase client and SQL migrations. ORM adoption may be revisited through a future ADR.

---

# Consequences

Positive:

* End-to-end TypeScript
* Minimal infrastructure overhead
* Excellent developer experience
* Strong PostgreSQL ecosystem
* Native Vercel support
* Tight Supabase integration

Negative:

* Vendor dependence on Supabase and Vercel
* App Router learning curve
* Server Components require disciplined architecture

These tradeoffs are accepted.

---

# Compliance

All production code shall conform to this technology stack unless superseded by an approved ADR.

No alternative framework, database, hosting platform, or UI framework may be introduced without architecture approval.
