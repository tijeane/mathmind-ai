# AI Collaboration & Development Policy

# Context

MathMind is being developed using AI-assisted engineering as a core development practice. AI tools accelerate software development, improve documentation quality, and automate repetitive engineering tasks.

To maintain consistency, security, and architectural integrity, all AI-generated contributions must follow a common engineering policy.

This ADR establishes the official AI collaboration standards for the project.

---

# Problem

Without a formal AI policy:

- Different AI assistants generate conflicting code.
- Architectural standards drift over time.
- Documentation becomes inconsistent.
- Security practices vary.
- Duplicate implementations appear.
- Technical debt accumulates rapidly.

The project requires deterministic AI collaboration rules.

---

# Decision

AI assistants are considered engineering collaborators.

All AI-generated work must follow the same governance, architecture, quality, security, and review standards as human-written code.

AI accelerates engineering—it does not replace engineering judgment.

---

# Approved AI Tools

The following tools are approved for project work:

| Tool | Primary Purpose |
|------|-----------------|
| ChatGPT | Architecture, design, implementation, documentation |
| Cursor | AI-assisted software development |
| Claude | Architecture review and long-form reasoning |
| GitHub Copilot | Code completion |
| Codex (future) | Automated engineering tasks |

Additional AI tools require engineering approval.

---

# AI Responsibilities

Before generating code, AI assistants shall:

1. Read the Project Handbook.
2. Review the Decision Index.
3. Read applicable ADRs.
4. Understand repository structure.
5. Respect frozen governance.
6. Avoid contradicting approved decisions.

AI must treat documentation as authoritative.

---

# Approved AI Activities

AI may assist with:

- Documentation
- Code generation
- Refactoring
- Testing
- SQL generation
- API development
- Architecture recommendations
- Performance optimization
- Bug analysis
- Technical writing
- Code review assistance

---

# Restricted Activities

AI shall not:

- Introduce new frameworks without an ADR.
- Modify governance documents without approval.
- Remove security controls.
- Bypass authentication.
- Disable testing.
- Commit secrets or credentials.
- Invent undocumented APIs.
- Change production architecture silently.

Major architectural changes always require a new ADR.

---

# Prompt Engineering Standards

Engineering prompts should:

- Be explicit.
- Reference existing documentation.
- Include architectural context.
- Define expected outputs.
- Specify constraints.
- Request production-ready solutions.

Well-structured prompts produce more reliable results.

---

# Documentation Requirements

Whenever AI changes behavior, it must update:

- Architecture documentation
- API documentation
- Database documentation
- Implementation notes
- ADR references (if applicable)

Documentation and implementation must remain synchronized.

---

# Code Quality Requirements

AI-generated code should be:

- Readable
- Modular
- Type-safe
- Well documented
- Secure
- Testable
- Maintainable
- Consistent with existing patterns

Generated code should prioritize clarity over cleverness.

---

# Security Requirements

AI-generated code shall:

- Validate all inputs.
- Avoid SQL injection.
- Use parameterized queries.
- Respect authentication.
- Respect authorization.
- Never expose secrets.
- Follow least-privilege principles.

Security standards apply equally to AI-generated and human-written code.

---

# Testing Requirements

AI-generated features should include:

- Unit tests
- Integration tests (when applicable)
- Edge-case validation
- Error handling
- Documentation updates

A feature without appropriate tests is not complete.

---

# Human Review

All AI-generated work requires engineering review before merge.

Reviewers should verify:

- Architectural compliance
- Documentation updates
- Security
- Testing
- Maintainability
- Performance
- Consistency with approved ADRs

AI suggestions are recommendations until approved.

---

# Traceability

Pull requests should identify AI involvement when significant.

Recommended metadata:

- AI tool used
- Scope of assistance
- Human reviewer
- ADR references
- Documentation updated

This improves transparency and historical traceability.

---

# Benefits

Adopting this policy provides:

- Consistent AI output
- Reduced technical debt
- Better documentation
- Faster development
- Improved onboarding
- Higher code quality
- Stronger architectural consistency

---

# Consequences

Positive:

- Reliable AI collaboration
- Predictable engineering practices
- Better governance compliance
- Easier code reviews

Trade-offs:

- AI-generated work requires review.
- Contributors must follow documented workflows.

These trade-offs are acceptable because AI is a productivity tool rather than an authority.

---

# Compliance

AI-generated work is considered complete only when:

- It follows approved ADRs.
- Documentation is updated.
- Tests are included where appropriate.
- Security requirements are met.
- Engineering review is complete.
